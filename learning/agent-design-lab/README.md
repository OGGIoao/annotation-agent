# Agent 设计学习实验室

> 本目录是 `annotation-agent` 的独立学习分支，不属于生产标注引擎的正式实现。
>
> 目的：边搭建一个小型、可运行、可测试的 Agent 玩具，边理解当前项目中的数据契约、工作流、结构化输出、工具调用、人工复核和评测方法。

## 为什么单独放置

主项目 `annotation-agent` 面向教育题目标注业务，必须保持领域模型、业务规则和生产架构的稳定。学习过程中会产生：

- 简化模型；
- 实验性代码；
- 失败案例；
- 教程和练习；
- 对框架的最小实现；
- 可能被推翻的设计。

这些内容不直接放入 `app/`、`rules/` 或主项目的正式文档，避免把学习实验误认为生产能力。

## 本分支要做什么

做一个与主项目同类、但规模更小的玩具：

> **Annotation Rover（标注小车）**：接收一张简化的练习页，先在离线环境中识别题目候选，生成结构化标注计划，经过规则校验后调用受控工具完成“贴框”和“确认”，最后返回可审计的执行结果。

它不连接真实标注平台，不处理真实用户数据，也不追求第一天接入 OCR 或大模型。它用固定的模拟页面和可替换的模型适配器，逐站长出能力。

## 与主项目的关系

```text
主项目：annotation-agent
  ├── 真实业务规则、领域模型、生产架构
  └── 目标：教育题目标注工作流

学习实验室：learning/agent-design-lab
  ├── 简化案例、练习、失败实验
  └── 目标：把 Agent 设计能力真正做出来
```

实验室只能借用主项目的概念，不能未经验证地修改主项目契约或规则。实验结果需要经过测试和复盘，才能考虑迁移到主项目。

## 本目录的完成标准

每一站都必须留下四类可验证产物：

1. 一份短教程：我理解了什么；
2. 一份可运行代码：我亲手实现了什么；
3. 一组测试：系统如何证明它工作；
4. 一份复盘：哪里失败、为什么、下次如何改。

只写教程而没有运行结果，不算完成；只跑通代码而不能解释设计，也不算完成。
